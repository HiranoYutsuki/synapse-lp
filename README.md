# シナプスAI LP内デモ

既存LPの「AI社員」の紹介直後に、AI社員を設定してチャットできる体験を追加しました。ページ遷移はありません。資料の白いチャット画面・グレーのサイドバー・青い吹き出しをもとにしています。

## できること

- エージェント名とAIへの指示を編集（この操作でAPIは呼びません）
- 架空の業務フロー画面（トリガー→ユーザー入力→AI処理→人間の確認→保存）のテスト実行、承認・修正依頼・却下
- 承認後の議事録のコピー
- ブラウザーごとの1日10回制限、全体の1日500回制限、1分3回制限
- スマートフォンでの縦並び表示

会話文はブラウザーのメモリーだけに保持され、再読み込みで消えます。サーバーは会話を保存しません。回数のカウントは再読み込みや会話のリセットで消えません。Googleには生成に必要な設定・メッセージ・直近2往復を送ります。

## ローカルで起動

Node.js 24 LTS推奨。追加パッケージのインストールは不要です。

1. `.env.example`を`.env.local`としてコピーする。
2. `.env.local`の`GEMINI_API_KEY=`にAPIキーを設定する。
3. Windowsは`start.cmd`をダブルクリックする。ターミナルからは`npm start`でも起動できます。
4. `http://127.0.0.1:8787/#demo`を開く。

このPCの作業用コピーには受領したキーを設定済みです。共有ZIPにはAPIキー・会話・利用カウントは含めていません。キーの取得先: https://aistudio.google.com/app/apikey

`start.cmd`はサーバーを背景で起動します。停止する場合は、Windowsのタスクマネージャーの「詳細」で`.data/server.pid`に記録されたPIDと、コマンドラインが`server/index.mjs`であることを確認して該当プロセスを終了してください。`npm start`の場合はそのターミナルでCtrl+Cです。

## APIキーを変更する

APIキーはコードには書かれていません。プロジェクト直下の`.env.local`の1行だけです。

```
GEMINI_API_KEY=ここに新しいキー
```

1. `.env.local`をメモ帳で開き、`GEMINI_API_KEY=`の後ろを新しいキーに書き換えて保存する（引用符・空白なし）。
2. `restart.cmd`をダブルクリックする。動いているサーバーを止め、新しいキーで起動し直します。
   - `start.cmd`だけでは、すでに起動中のサーバーがそのまま使われ、新しいキーが反映されません。
   - `npm start`で起動している場合は、そのターミナルでCtrl+Cを押してから`npm start`し直します。
3. 古いキーが不要なら、AI Studioで削除（無効化）してください。

キーを読み込んでいるのは`server/index.mjs`の`env.GEMINI_API_KEY`です。公開サーバーで動かす場合は、ホスティング先の環境変数`GEMINI_API_KEY`を書き換えて再起動します。

## 構成

`ブラウザー内のLP → 同じPCのNodeサーバー → Gemini API`

- `index.html`：既存LPと埋め込みデモ
- `assets/demo.css`：デモ専用の見た目
- `assets/demo.js`：設定、会話、入力チェック、状態表示
- `server/index.mjs`：APIキーを保持しGeminiへ接続、静的ファイルを限定配信
- `server/limits.mjs`：回数を`.data/usage.json`へ保存
- `restart.cmd` / `restart.ps1`：サーバーを再起動（APIキー変更後に使用）
- `.env.example`：`.env.local`のひな形
- `server/demo.test.mjs`：入力制限、回数制限、キー非配信、同時送信などのテスト

Cloudflare Worker・Cloudflare Secretは使用しません。APIキーは`.env.local`から環境変数として読み込み、ブラウザーへ配信しません。`.env.local`と`.data`はGitから除外しています。

## Geminiの利用と料金

2026年9月24日の公式料金表で、`gemini-3.1-flash-lite`のStandardには無料枠があります。無料枠を利用するプロジェクトならモデルの入出力料金は0円です。このアプリから請求設定・有料プランへの変更は行いません。ただし、キーだけではプロジェクトの請求プランを確認できません。実際の無料枠・利用上限はAI Studioで確認してください。

- 1メッセージにつき1回だけAPIを呼びます。自動再試行や別モデルへの切り替えはありません。
- メッセージは最大500文字、設定ルールは最大240文字。
- 履歴は直近2往復・合計4,000文字以内、出力は最大512トークン。
- 生成内容は目安350文字以内。上限で途中までになった場合は画面に表示します。
- 上限・障害の場合はエラーを表示します。生成したように見せた固定文には置き換えません。
- 天気などのリアルタイム検索、外部サービスへの操作は実装していません。
- 無料枠の入力はGoogleの製品改善に利用される場合があります。架空のサンプルを使い、個人情報や社外秘を入力しないでください。

前の提案資料の「出力250トークン」は料金計算の例でした。この実装では、日本語の議事録が途中で切れにくいよう最大512トークンにしています。将来有料枠を選ぶ場合、公式Standard単価はテキスト入力$0.25/100万トークン、出力$1.50/100万トークンです。実際の費用は履歴を含む入出力量とプロジェクトのプランで変わります。

公式: https://ai.google.dev/gemini-api/docs/pricing

キーの扱い: https://ai.google.dev/gemini-api/docs/api-key

## 利用制限の仕組み

署名付きHttpOnly Cookieでブラウザーを識別します。日本時間0時で日次カウントが更新されます。Googleへ送る前に枠を確保するため、APIエラーやタイムアウトも1回として数えます。入力エラー、上限超過、同時送信の拒否では枠を消費しません。

「1ブラウザー10回」は本人認証ではありません。Cookieの削除や別ブラウザーでは別セッションになり、全体500回の上限が最終的な制限になります。Google側の無料枠が先に上限に達する場合もあります。

回数の保存は1つのNodeプロセスを前提とします。`.data`を削除すると回数と署名キーがリセットされます。公開運用で複数プロセスを使う場合は共有DBへ置き換えてください。

## 公開LPへ反映する場合

この版はローカルで完成させたもので、既存のGitHub Pagesには反映していません。GitHub Pagesだけではサーバー側APIを実行できません。

公開時は、このNodeアプリを実行できるホスティングへLPとAPIを一緒に配置する方法が簡単です。公開先の`PUBLIC_ORIGIN`を設定し、必要に応じて`HOST=0.0.0.0`とホスティング指定の`PORT`を設定します。HTTPS、1プロセス、永続化された`.data`、非公開の環境変数が必要です。公開サーバーの環境変数へキーを設定し、`.env.local`はアップロードしません。サーバーの利用料金はホスティング先に依存します。

GitHub Pagesを引き続き使う構成には、別のAPIホストとOrigin/Cookieの設計が必要です。現在の実装は同一Origin用です。

## 動作確認

`npm test`で、Geminiを呼ばない7件の自動チェックを実行できます。子プロセスが制限される環境では`node --test --test-isolation=none server/demo.test.mjs`を使用してください。

実APIでは架空メモの議事録化、会話を踏まえた短縮、天気への自由入力応答を確認しています。使用したAPIキーはテストや共有ファイルに含めません。
